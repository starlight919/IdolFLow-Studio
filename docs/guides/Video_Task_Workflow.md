# 视频任务完整工作流

> 最后更新：2026-08-15

## 概述

IdolFlow Studio 的视频生成以「任务文件夹」为中心。同一任务文件夹可创建多个不同任务（如「唱歌版」「跳舞版」），共享 Anchor 正式图和原始素材。

## 启动服务

```bash
bash scripts/start.sh         # 前台（开发）
bash scripts/start-daemon.sh  # 后台
bash scripts/stop.sh          # 停止
bash scripts/status.sh        # 查看状态
```

Web 工作台：**http://127.0.0.1:8913/**

提交密码保护付费 API 操作（生成），浏览/审核/下载不需要密码。

## 任务结构

```
data/<任务文件夹>/
├── anchors/                  # Anchor 图片（上传 / 设为 Anchor 统一落点，Video 任务引用这里）
│   ├── anchor-references/    # 参考图片
│   └── generated/<run_id>/   # 生成候选
├── references/               # 参考音视频（视频 + 音频统一落点）
│   ├── 参考.mov
│   └── 参考.mp3
├── tasks/                    # 每个 .json 文件一个任务
│   ├── 唱歌版.json
│   └── 跳舞版.json
└── seedance/                 # Seedance 素材缓存（内部目录，自动生成）
```

任务 ID 格式：`任务文件夹__任务名称`（如 `马路风__唱歌版`）

## 三种模式

| 模式 | 用途 | 传视频 | 传音频 | 需要歌词 |
|------|------|--------|--------|----------|
| `lip_sync` | 纯对口型 | 可选 | 可选 | 是 |
| `motion` | 纯动作模仿 | 强制 | 不传 | 否 |
| `dance_lip_sync` | 口型+动作 | 强制 | 可选（默认传） | 是 |

### 关于音频/视频传入

**`lip_sync`（纯对口型）** 支持三条驱动路径：

| 传视频 | 传音频 | 驱动方式 | 说明 |
|--------|--------|----------|------|
| ✅ | ❌ | 视频驱动 | 只传参考视频，Seedance 从视频中学习口型+画面 |
| ❌ | ✅ | 音频驱动 | 只传音频，Seedance 纯音频对口型（无参考画面） |
| ✅ | ✅ | 音视频驱动 | 传视频 + 从视频提取的音频，口型精度最高 |

**`motion`（纯动作模仿）**：必须传参考视频，不涉及音频。Seedance 模仿视频中的动作。

**`dance_lip_sync`（口型+动作）**：必须传参考视频，音频可选（默认勾选）。视频用于模仿动作，勾选后从视频提取音频一并上传以提升口型精度。

> **注意**：无论是否传音频给 Seedance，mux 阶段始终会用原始音频回灌到 `final.mp4`。`pass_reference_audio` 只控制是否将音频传给 Seedance 用于生成过程。

#### 参考音频的三种输入场景（切换时不要混）

参考音频有三种输入场景，靠「📹 视频 / 🎵 音频」两个 tab 区分：

| 场景 | 操作 | 传视频 | 音频来源 | 提交内容 |
|------|------|--------|---------|---------|
| **① 视频 + 视频提取音频**（可选用不用） | 📹 视频 tab 选视频，勾选/取消「传参考音频」 | ✅ | **从视频提取** | 视频 + 音频（勾选时） |
| **② 纯音频** | 🎵 音频 tab 选音频 | ❌ | 音频文件本身 | 只传音频 |
| **③ 视频 + 独立音频** | ❌ **不提供**（由 ① 覆盖） | — | — | — |

- **不提供"视频 + 独立音频"的独立入口**：传参考视频时，音频**一律从视频提取**。若你在音频 tab 选过音频又切到视频 tab，会提示「音频将被忽略，音频以视频提取为准」——避免两类音频来源混淆。
- **保存按当前 tab 决定类型**：停在「🎵 音频」tab 保存 → 纯音频任务（`pass_reference_video=false`）；停在「📹 视频」tab 保存 → 视频任务。二者不会同时混入。
- **把视频任务改成纯音频**：编辑任务回填时，纯音频任务会自动清空视频字段、视频任务会自动清空音频字段，互斥；只需切到「🎵 音频」tab 重新选音频后保存。
- **纯音频任务无 pad_mode**：音频 tab 时长对齐固定为「原始时长（none）」，不参与 `pad_mode` 处理。
- 详细设计见 [Asset_Design.md](Asset_Design.md) §4.1。

## 创建任务

在 Web 工作台「视频任务」面板：

1. 选择生成模式
2. 填写任务名称 + 选择数据文件夹
3. 设置候选数（默认 4）
4. 填写参考视频文件（每行一个），通过 📹/🎵 标签页可切换填写独立音频文件
5. 选择时长对齐模式（默认"原始时长"，可选"前面补齐"或"后面补齐"）
6. `lip_sync` 模式可选"传参考视频"/"传参考音频"；`dance_lip_sync` 视频强制、音频可选；`motion` 不显示音频选项
7. 对口型模式填写歌词（直接填写即可，无需打时间戳）
8. （可选）如需精确口型对齐，点歌词框下方「打时间戳（可选）>」为每句歌词打时间戳，详见 [Singing_Video_Guide.md](Singing_Video_Guide.md)
9. 可选填写额外约束（如"减小动作幅度，不要笑"）
10. （可选）展开「高级视频设置」调整分辨率、宽高比、生成音频、水印、输出格式。折叠状态下 summary 会显示当前默认值（720p · 9:16 · 无音频 · 无水印 · MP4），无需展开即可判断是否需要调整。生成音频和加水印是 toggle 开关，分辨率/宽高比/输出格式是下拉选择
11. 保存任务 → 提交生成

> 素材选择：Anchor 与参考音视频以「标签 chips」展示，点「✕」取消选中（不删除磁盘文件）。上传素材后文件持久化到任务文件夹，之后可直接通过「选择文件」引用，无需重复上传。详见下文「素材管理约定」。

## 素材管理约定

### 文件位置约定

所有素材统一按类型存放在任务任务文件夹（`data/<任务文件夹>/`）下的固定子目录：

| 素材 | 约定位置 | 来源 |
|------|---------|------|
| Anchor 参考图 | `anchors/anchor-references/` | 本机上传 / 从任务文件夹选择 / 用户手动放置 |
| Anchor 候选图 | `anchors/generated/<run_id>/` | 现场生成（内部目录） |
| Anchor 正式图 | `anchors/`（根目录） | 上传 或 审核时「设为 Anchor」复制而来（视频任务引用这里） |
| 参考视频 | `references/` | 上传（固定落点）/ 用户手动放置 |
| 参考音频 | `references/` | 上传（固定落点）/ 用户手动放置 |

> **统一约定**：图片存放于 `anchors/`，音视频（视频 + 音频）存放于 `references/`。任务目录根目录仅用于内部目录（`anchors/`、`references/`、`tasks/`、`seedance/`），不放素材文件。
>
> **上传固定落点**：通过浏览器「上传素材」时，图片固定存到 `anchors/`，音视频固定存到 `references/`。
>
> **手动放置**：用户自行往任务目录放素材时，图片放 `anchors/`、音视频放 `references/`（即与上传落点一致）。
>
> **引用路径**：所有 `file` 字段统一存「相对任务目录的路径」，带子目录前缀（如 `anchors/xxx.png`、`references/xxx.mov`），后端 `task_dir + file` 解析；找不到时再回退到 `data_root + file` 查找（兼容历史根目录写法）。
>
> **历史数据迁移**：早期版本视频/音频可能散落在任务根目录或 `audio/` 子目录，已一次性迁移到 `references/`（图片迁到 `anchors/`），并同步更新已保存任务的引用路径。

### 任务文件夹前置校验

- 未填写「任务文件夹」时，素材面板提示「请先选择任务文件夹」，且「上传素材」按钮与文件选择框禁用。
- 已填写但目录缺素材时，提示分两类分别给出引导，且操作入口**可点击跳转**（点击后滚动到对应区域并高亮闪烁）：
  - 缺 Anchor 图片 → 「去现场生成」/「去上传」，或手动放入 `anchors/`；
  - 缺参考音视频 → 「去上传」，或手动放入 `references/`。
- 目录内素材齐全时，提示自动隐藏。

### Anchor 获取方式

- Anchor 字段提供两个**同级操作**：「选择文件」（从已有图片中选）与「现场生成」（用 GPT Image 2 生成候选）。
- 「现场生成」采用**两步交互**：点击后先展示说明（使用 GPT Image 2 现场生成候选，审核后可加入当前任务），再点「打开 Anchor 生成器」跳转；跳转后回到 Anchor 页面顶部。
- 「现场生成」只针对 Anchor，不影响参考音视频、歌词、约束（这些始终显示）。

### 选择文件交互

- 「选择文件」默认直接进入约定子目录（Anchor → `anchors/`，音视频 → `references/`）；若子目录不存在，自动逐级回退到任务根目录。
- 选择 Anchor 图片时，文件列表会为每张图片显示**缩略图预览**，方便辨认；选择音视频时不显示缩略图。
- 若存在 `generated/` 目录（现场生成的候选，尚未「设为 Anchor」），选择 Anchor 图片时会提示「现场生成的候选在 generated/ 里」（根目录已有图时改为更轻的提示），进入后说明如何「设为 Anchor」固定到正式目录。
- **主目录回退引导**：当素材放在任务主目录（而非约定子目录）时，进入默认子目录后若当前目录无可选文件、而主目录存在同类文件，列表顶部会显示引导条「💡 当前目录没有可选音视频/图片，主目录里有 N 个 → 去主目录」，点击即可跳转到主目录查看。
- 选参考音视频时，picker 会过滤掉 Anchor 图片相关目录（`anchors/` 等），只显示音视频；选 Anchor 时只显示图片。
- 选参考音视频时**根据所选文件自动切换标签页**：全为音频 → 自动切「🎵 音频」；含视频 → 切「📹 视频」。
- 已选参考音视频缩略图**支持点击预览**：音频（♪ 图标）点击弹出内嵌播放器试听，视频缩略图点击弹出播放器预览；点击遮罩关闭，播放器本体可正常操作（进度条等）。

### 切换任务文件夹

- 切换任务文件夹时，若已填写素材 / 歌词 / 附加约束 / 自定义 Prompt，会先弹窗提醒（切换会清空这些内容），确认后才切换并清空；取消则保持原状。
- 清空范围：Anchor 图片、参考音视频、歌词、附加约束、自定义 Prompt（均属于原任务文件夹的内容）。
- 这避免了「上一个文件夹的内容残留到新文件夹」的数据串扰。

### 删除任务文件夹

- 文件夹选择器在**顶层**（`data/` 根）为每个一级任务文件夹提供「🗑 删除」按钮，用于删除整个任务文件夹。
- 删除前会弹出**确认弹窗**，以**级联树状结构**展示将删除的完整层级（目录 → 每个任务及其运行数 → 素材/缓存），底部汇总任务与运行总数。
- 级联清理范围（不可恢复）：
  - 任务定义 `tasks/*.json`
  - Anchor 图片 / 候选 / 正式图（`anchors/` 整个子目录）
  - 参考音视频（`references/`）
  - Seedance 素材缓存（`seedance/`）
  - 所有关联运行记录，及 `runtime/outputs/<目录>/`、`runtime/work/<目录>/` 下的生成产物
  - 最后删除整个 `data/<目录>/`
- 仅对 `data/` 下的一级任务文件夹生效（不作用于内部子目录，也无法删除 `data/` 根）。

### 编辑回填

- 编辑已保存任务时，纯音频任务（`pass_reference_video=false`）自动切「🎵 音频」标签页，音频文件回填到音频字段；视频任务切「📹 视频」标签页。
- 编辑任务后页面滚动定位到「素材」区，方便直接查看已选素材与现场生成候选提示。

### 取消与保存方式

- **取消 / 新任务**：顶部按钮在「新建」状态下显示「新任务」（清空重来）；「编辑」已保存任务时变为「取消」（放弃修改并清空表单）。取消后需重新选择任务文件夹。
- **保存方式**：编辑并改了任务名或文件夹后点保存，会询问「保存为新任务」还是「更新原任务」——前者保留旧任务新建一份，后者覆盖旧任务。
- **保存宽松**：保存草稿只需任务名 + 文件夹，歌词/素材不全也能保存；生成时才严格校验歌词与素材。

### 缺失素材检测

- 编辑任务时，后端会检测任务引用的 Anchor 图片 / 参考音视频是否**仍存在于磁盘**。
- 若有文件已不存在（例如被删除），素材区顶部会显示红色警告条，列出缺失文件名，并在对应预览图上标记「文件已不存在」。
- 此时需要在素材区移除或重新选择，否则保存 / 生成会失败。
- Seedance 素材缓存（`seedance/`）会**保留**，不会因文件缺失而清理——文件重新选回且内容一致时可直接复用，无需重新上传。
- Asset 面板会标记每个素材的复用/重传状态（由统一决策引擎判定）：🟢 复用已上传资源 / 🔄 将重新生成并上传 / ⚠️ 需重新选择等。完整设计见 [Asset_Design.md](Asset_Design.md)。

### 保存路径约定

任务保存时，`file` / `audio_file` 字段统一存**「相对任务任务文件夹（`data/<任务文件夹>/`）的路径」**，带子目录前缀（如 `anchors/xxx.png`、`references/xxx.mp3`）。后端按 `task_dir + file` 解析绝对路径，找不到时再回退到 `data_root + file` 查找（兼容历史根目录写法）。

> 界面展示只显示任务文件夹名（`data_dir`，如「马路风」），而文件实际分布在 `anchors/`、`references/` 等子目录中，两者不冲突——`file` 字段统一相对任务目录，路径自洽。

### 纯音频驱动

纯音频任务（只传 `.mp3` 等音频、不传视频）后端会跳过参考视频切片，只准备音频，走「图片 + 音频」的口型生成流程，不再对音频文件执行视频处理。

## 生成流程

提交后系统自动完成：

1. **Prepare** — 校验素材、提取音频、截取参考视频、补足时长对齐（按源文件指纹判断是否需要重建处理产物）
2. **Tunnel** — 启动素材隧道
3. **Upload** — 上传 Anchor 图片、参考视频、音频到 Seedance（**按文件指纹 + 处理参数自动复用/重传**：源文件与处理参数未变则复用已上传的 asset，任一变化则自动重新上传，详见 [Asset_Design.md](Asset_Design.md)）
4. **Submit** — 提交 Seedance 生成任务
5. **Poll** — 轮询等待完成，每完成一个候选立即写入 manifest
6. **Download** — 下载 result.mp4
7. **Mux** — 回灌原始音频 → final.mp4
8. **Manifest** — 生成审核清单

## 恢复轮询（服务重启后）

- 生成过程中若服务重启，**已提交** Seedance 的候选会从磁盘状态自动恢复轮询，无需手动操作。
- 若运行因故中断（例如尚未提交即中止），运行记录会标记为 failed，并提供「恢复」按钮：点击后凭已提交候选的 `task_id` 继续轮询下载，**不重新提交**。
- 恢复轮询仅依赖参考音视频（用于下载后的裁剪与回灌音频），**不依赖 Anchor 图片**——即使 Anchor 图片被删除，只要参考音视频仍在，已提交的候选即可恢复。

## 时长处理

Seedance API 的 `duration` 参数要求整数秒。系统会自动向上取整（`ceil`），同时根据 `pad_mode` 选择如何补足到整数秒。

### 三种 pad_mode 模式

在参考音视频区域可选择时长对齐策略：

| 模式 | 说明 | 视频处理 | 音频处理 | 回灌处理 |
|------|------|----------|----------|----------|
| `back`（默认） | 末尾补齐 | `tpad=stop_mode=clone` 末尾克隆最后一帧 | `apad=whole_dur` 末尾补静音 | mux 用 `-shortest` 自动裁掉末尾多余部分 |
| `front` | 前面补齐 | `tpad=start_mode=clone` 开头克隆第一帧 | `concat` 开头拼接静音 | 先 `-ss` 裁掉前面的 padding，再 mux |
| `none` | 原始时长 | 不补帧，截取原始时长 | 不补静音 | mux 用 `-shortest` 以原始音频为准 |

### 设计思路

- **`back`（末尾补齐）**：最常用的模式。视频末尾静止帧 + 静音不会影响主体内容，Seedance 生成的视频末尾也会是相对静止的画面，mux 时用原始音频的 `-shortest` 自然裁回原始长度。

- **`front`（前面补齐）**：适用于口型同步场景。有些视频开头就有快速口型变化，末尾补齐可能导致口型延迟（Seedance 需要处理额外的静止帧）。前面补齐让 Seedance 从静止帧开始"预热"，到达真实内容时口型更准确。代价是 mux 后需要先裁掉前面的 padding。

- **`none`（原始时长）**：不补齐，直接用原始时长提交。适合不想引入任何额外帧的场景，但 Seedance 仍要求 `duration` 为整数秒，实际提交的 `seedance_duration` 仍为 `ceil(total)`，视频本身不补帧。

### 示例流程（17.857s 视频，ceil=18s）

```
原始视频: 17.857s

─── back 模式 ───
trim+tpad(末尾补): 18.000s → Seedance → 18.000s → mux(-shortest) → 17.857s

─── front 模式 ───
trim+tpad(前面补): 18.000s → Seedance → 18.000s → 裁前面0.143s → mux → 17.857s

─── none 模式 ───
trim(不补): 17.857s → Seedance(ceil=18) → ~18.000s → mux(-shortest) → 17.857s
```

- Seedance 2.5 上限 30s，非 2.5 上限 15s
- 补帧量 = `ceil(total) - total`（如 17.857s → 补 0.143s）
- mux 阶段始终用原始音频回灌到 `final.mp4`

## 配置

常用环境变量（`.env`）：

| 变量 | 说明 |
|------|------|
| `VIDEO_DATA_ROOT` | 任务文件夹根路径 |
| `VIDEO_WORK_ROOT` | 临时工作目录 |
| `VIDEO_OUTPUT_ROOT` | 输出目录 |
| `VIDEO_WEB_PORT` | Web 端口（默认 8913） |
| `VIDEO_MAX_CONCURRENT_RUNS` | 最大并发运行数 |
| `VIDEO_SUBMIT_SECRET` + `VIDEO_SUBMIT_HASH` | 提交密码（HMAC，用 `scripts/gen_password.py` 生成） |
| `VIDEO_PUBLISH_ENABLED` | 是否启用发布 |

API key 和 token 只放在 `.env`，不写入任务 JSON。
